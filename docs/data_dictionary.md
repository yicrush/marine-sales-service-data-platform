# Data Dictionary

Status: Draft v0.1  
Scope: Quotation data model  
Target database: PostgreSQL

## Purpose

This document defines the meaning, source, transformation rules, and nullability of each column in the quotation database. The definitions are based on the current ERD and the first manually loaded M quotation (`KP-M-Q-26-001`). They will be revised as more M and O quotations are tested.

## General Conventions

- Primary keys are generated by PostgreSQL unless the table uses a composite primary key.
- `NULL` means that a value is missing, unknown, or not applicable. It is different from zero or an empty string.
- Source text should be preserved without correcting spelling or grammar unless a separate transformation rule states otherwise.
- Monetary values are stored as decimal numbers. Currency is stored at the quotation level.
- Fields that do not apply to a quotation type do not require placeholder rows. For example, an M quotation without a KIT or service scope has no corresponding rows in `kit_components` or `service_details`.
- `line_text_raw` preserves the complete item-related source text. Parsed fields such as `item_name`, `description`, and `part_no` may remain `NULL` when the text cannot be separated reliably.

## `customers`

Stores customer companies shown in the `TO` field of quotations.

| Column | Type | Key | Nullable | Definition | Source / rule | Example |
|---|---|---|---|---|---|---|
| `customer_id` | integer | PK | No | Internal identifier for a customer. | Generated by PostgreSQL. | `1` |
| `customer_name` | text |  | No | Customer company name or the customer label used by the business. | Extract from `TO`. Preserve the source value until a customer-name standardization process is defined. | `EPS` |
| `created_at` | date |  | No | Date on which the customer record was created in the database. | Defaults to the database insertion date. This is not the quotation date. | `2026-09-14` |

## `contacts`

Stores customer contacts shown in the `ATTN`, telephone, and email fields.

| Column | Type | Key | Nullable | Definition | Source / rule | Example |
|---|---|---|---|---|---|---|
| `contact_id` | integer | PK | No | Internal identifier for a contact. | Generated by PostgreSQL. | `1` |
| `customer_id` | integer | FK | No | Customer company to which the contact belongs. | Reference `customers.customer_id`. | `1` |
| `contact_name` | text |  | Yes | Name of the customer contact. | Extract from `ATTN`. Use `NULL` when the field is blank. | `Rubine Ramasamy` |
| `telephone` | text |  | Yes | Contact telephone number as written in the source. | Preserve symbols, spaces, and country code. | `+65 6000 0000` |
| `email` | text |  | Yes | Contact email address as written in the source. | Use `NULL` when not provided. | `contact@example.com` |

## `vessels`

Stores the current known master record for each vessel.

| Column | Type | Key | Nullable | Definition | Source / rule | Example |
|---|---|---|---|---|---|---|
| `vessel_id` | integer | PK | No | Internal identifier for a vessel. | Generated by PostgreSQL. | `1` |
| `customer_id` | integer | FK | No | Customer currently associated with the vessel. | Reference `customers.customer_id`. | `1` |
| `vessel_name` | text |  | Yes | Standard vessel name. | Extract from `VESSEL NAME` and standardize only when a matching rule is defined. | `MOUNT GILBOA` |
| `hull_no` | text |  | Yes | Hull number associated with the vessel. | Extract from `HULL NO.` or `SHIPYARD/HULL NO.`. Use `NULL` when blank. | `SN2293` |
| `steering_gear_type` | text |  | Yes | Current known steering gear model or type installed on the vessel. | Populate only when confirmed. | `FE21-350` |
| `main_pump_type` | text |  | Yes | Current known main pump model or type. | Populate only when confirmed. | `LV-260` |
| `servo_pump_type` | text |  | Yes | Current known servo pump model or type. | Populate only when confirmed. | `JP20` |

## `quotations`

Stores one record per quotation reference number, including header information and terms.

| Column | Type | Key | Nullable | Definition | Source / rule | Example |
|---|---|---|---|---|---|---|
| `quotation_id` | integer | PK | No | Internal identifier for a quotation. | Generated by PostgreSQL. | `1` |
| `quotation_ref_no` | text | UNIQUE | No | Complete quotation reference number. | Preserve the complete `REF. NO.` value, including any suffix. | `KP-M-Q-26-001` |
| `quotation_type` | text |  | No | Business quotation category encoded in the reference number. | `M` for item, spare, or KIT quotations; `O` for service quotations. | `M` |
| `quotation_year` | integer |  | Yes | Four-digit year encoded in the reference number. | Convert the two-digit year segment to four digits. | `2026` |
| `sequence_no` | integer |  | Yes | Sequential quotation number encoded in the reference number. | Convert the numeric sequence segment to an integer. Leading zeros are not retained here. | `1` |
| `suffix` | text |  | Yes | Trailing reference-number segment, when present. | Preserve as text because its meaning is not yet confirmed. Use `NULL` when absent. | `01` |
| `customer_id` | integer | FK | No | Customer receiving the quotation. | Reference `customers.customer_id`. | `1` |
| `contact_id` | integer | FK | Yes | Customer contact addressed by the quotation. | Reference `contacts.contact_id`. Use `NULL` when `ATTN` is blank. | `1` |
| `quotation_date` | date |  | Yes | Date shown on the quotation. | Convert the source date to ISO date format. | `2026-01-06` |
| `subject` | text |  | Yes | Heading that describes the quotation scope or work. | Preserve the heading above the item or service section. | `SPARES FOR D/M` |
| `currency` | char(3) |  | No | ISO-style currency code used for quotation amounts. | Default to `USD` only when the document clearly uses USD or the business rule confirms it. | `USD` |
| `lead_time_text` | text |  | Yes | Complete lead-time statement. | Preserve the text after `LEAD TIME`. Do not convert ranges to one number. | `2~3 weeks after firm order` |
| `delivery_terms` | text |  | Yes | Delivery term stated on the quotation. | Preserve the source text. | `Ex-work Korea` |
| `payment_terms` | text |  | Yes | Payment condition stated on the quotation. | Preserve the source text. | `30 Days after Invoice date` |
| `additional_terms` | text |  | Yes | Other quotation-level conditions not represented by the defined term columns. | Preserve the complete source statement. | `NULL` |

## `quotation_vessels`

Links quotations and vessels. This table supports quotations that cover more than one vessel and preserves the vessel text shown in the quotation.

| Column | Type | Key | Nullable | Definition | Source / rule | Example |
|---|---|---|---|---|---|---|
| `quotation_id` | integer | PK, FK | No | Quotation associated with the vessel. | Reference `quotations.quotation_id`. Forms a composite PK with `vessel_id`. | `1` |
| `vessel_id` | integer | PK, FK | No | Matched vessel master record. | Reference `vessels.vessel_id`. Forms a composite PK with `quotation_id`. | `1` |
| `quoted_vessel_name` | text |  | Yes | Vessel name exactly as shown in the quotation. | Preserve source spelling and formatting. | `MOUNT GILBOA` |
| `quoted_hull_no` | text |  | Yes | Hull number exactly as shown in the quotation. | Use `NULL` when the source field is blank. | `NULL` |

## `quotation_items`

Stores priced or quoted lines from M and O quotation bodies. A row may represent a part, KIT, service, expense, or another commercial item.

| Column | Type | Key | Nullable | Definition | Source / rule | Example |
|---|---|---|---|---|---|---|
| `quotation_item_id` | integer | PK | No | Internal identifier for a quotation line. | Generated by PostgreSQL. | `1` |
| `quotation_id` | integer | FK | No | Quotation containing the line. | Reference `quotations.quotation_id`. | `1` |
| `line_no` | integer |  | Yes | Line number shown in the quotation. | Convert a numeric `No.` value to an integer. Do not create a number when the source has none. | `1` |
| `line_text_raw` | text |  | Yes | Complete item-related source text for the quotation line. | For a combined Description cell, preserve the complete cell including line breaks. When ITEM and Description are separate, combine both with explicit `ITEM:` and `DESCRIPTION:` labels. | `The full set of handle\n(1)wheel ...` |
| `item_type` | text |  | No | Standard classification of the quoted line. | Allowed values: `PART`, `KIT`, `SERVICE`, `EXPENSE`, `OTHER`, `UNKNOWN`. Use `UNKNOWN` when classification is uncertain. | `PART` |
| `item_name` | text |  | Yes | Short parsed name of the quoted item. | Populate only when a distinct item name can be identified reliably. | `The full set of handle` |
| `description` | text |  | Yes | Parsed specification or detailed description of the quoted item. | May contain the same source text as `line_text_raw` when reliable separation is not possible. | `(1)wheel ... (4) bottom holder with thread` |
| `part_no` | text |  | Yes | Part number, product code, or other unique component identifier. | Populate only when explicitly stated or reliably parsed. | `NULL` |
| `quantity` | integer |  | Yes | Number of quoted units for the line. | Extract from `Qty`. | `4` |
| `quantity_unit` | text |  | Yes | Unit associated with the quantity. | Preserve units such as `pcs`, `set`, or `box`. Use `NULL` when not shown. | `NULL` |
| `unit_price` | numeric(14,2) |  | Yes | Price per quoted unit before line-level multiplication. | Extract from `U/PRICE`. | `800.00` |
| `base_amount` | numeric(14,2) |  | Yes | Line amount before discount. | Use the stated pre-discount amount. If it is not stated but quantity and unit price are available, calculate `quantity * unit_price`. | `3200.00` |
| `discount_rate` | numeric(5,2) |  | Yes | Explicit line discount percentage. | Populate only when a discount rate is explicitly stated. `NULL` means no rate was provided; it does not mean zero. | `NULL` |
| `quoted_amount` | numeric(14,2) |  | Yes | Final line amount offered to the customer after any discount. | Use the final displayed line amount. When there is no discount, this normally equals `base_amount`. | `3200.00` |
| `remark` | text |  | Yes | Remark associated with the quotation line. | Preserve the source text. | `NULL` |

## `kit_components`

Stores component rows from a separate KIT Details file or sheet. No rows are created when a quotation has no KIT details.

| Column | Type | Key | Nullable | Definition | Source / rule | Example |
|---|---|---|---|---|---|---|
| `kit_component_id` | integer | PK | No | Internal identifier for a KIT component row. | Generated by PostgreSQL. | `1` |
| `kit_quotation_item_id` | integer | FK | No | KIT-type quotation line described by the component row. | Reference `quotation_items.quotation_item_id`. | `5` |
| `component_group` | text |  | Yes | Section under which the component appears. | Standard values currently include `Main Pump`, `Servo Pump`, `Line Filter`, and `Others`. | `Main Pump` |
| `line_no` | integer |  | Yes | Component line number shown in the KIT Details source. | Convert numeric values to integers. | `1` |
| `part_name` | text |  | Yes | Name of the KIT component. | Extract from `Parts name`. Preserve source wording. | `O-Ring` |
| `part_no` | text |  | Yes | Part number of the KIT component. | Extract from `Parts No.`. | `OR-001` |
| `quantity` | integer |  | Yes | Number of component units included or quoted. | Extract the numeric part of the quantity. | `2` |
| `quantity_unit` | text |  | Yes | Unit associated with the component quantity. | Preserve values such as `pcs`, `set`, or `box`. | `pcs` |
| `unit_price` | numeric(14,2) |  | Yes | Unit price of the component in the quotation currency. | Extract from `Unit Price`. | `10.00` |
| `amount` | numeric(14,2) |  | Yes | Total amount for the component row. | Use the displayed amount or calculate `quantity * unit_price` when appropriate. | `20.00` |
| `remark` | text |  | Yes | Remark associated with the component row. | Preserve source text. | `NULL` |

## `service_details`

Stores service-specific conditions for an O quotation. `quotation_id` is both the PK and FK, so a quotation can have at most one service-details row. No row is created for an M quotation without a service scope.

| Column | Type | Key | Nullable | Definition | Source / rule | Example |
|---|---|---|---|---|---|---|
| `quotation_id` | integer | PK, FK | No | Service quotation described by this row. | Reference `quotations.quotation_id`. | `10` |
| `working_place` | text |  | Yes | Planned country, port, shipyard, or other work location. | Preserve the source text. | `CHINA` |
| `service_engineer_count` | integer |  | Yes | Number of company service engineers planned for the work. | Extract from the service engineer statement. | `2` |
| `supporting_worker_count` | integer |  | Yes | Number of supporting shipyard or customer workers. | Extract only when explicitly stated. | `1` |
| `working_days` | integer |  | Yes | Planned number of work or service days. | Preserve the document's stated count. The treatment of travelling days is recorded separately. | `8` |
| `includes_travel_days` | boolean |  | Yes | Whether `working_days` includes travelling days. | `TRUE` when explicitly included, `FALSE` when explicitly excluded, and `NULL` when unclear. | `TRUE` |
| `working_details` | text |  | Yes | Description or reference range for the planned work scope. | Preserve the source text, such as an A-to-K reference. | `A to K` |
| `steering_gear_type` | text |  | Yes | Steering gear type stated in this quotation. | Preserve as a quotation-time snapshot, even if the vessel master is later updated. | `FE21-350` |
| `main_pump_type` | text |  | Yes | Main pump type stated in this quotation. | Preserve as a quotation-time snapshot. | `LV-260` |
| `servo_pump_type` | text |  | Yes | Servo pump type stated in this quotation. | Preserve as a quotation-time snapshot. | `JP20` |

## Open Questions and Proposed Schema Changes

The following items require confirmation through additional manual loading. They are not yet part of `schema.sql`.

1. **Document total**  
   Consider adding `quotations.document_total_amount NUMERIC(14,2)` to preserve the total displayed in the source document. This would allow a data-quality check against the sum of `quotation_items.quoted_amount`.

2. **Source traceability**  
   Determine whether to add `source_file_name` and `source_sheet_name`, or create a separate source-document table. This is important because quotations, KIT details, and cost files may be stored separately.

3. **Reference-number suffix**  
   Confirm whether a suffix represents a revision, an alternative quotation, or another business distinction before creating parent/revision relationships.

4. **Customer and vessel history**  
   Confirm whether vessel ownership changes need to be tracked historically. The current model stores one customer on each vessel and preserves quotation-time text in `quotation_vessels`.

5. **Quantity precision**  
   Confirm whether quotation or KIT quantities can be fractional. If so, change `quantity` from `INTEGER` to `NUMERIC`.

6. **Component groups**  
   Confirm whether groups other than `Main Pump`, `Servo Pump`, `Line Filter`, and `Others` occur before enforcing a fixed category list during extraction.

7. **Item classification**  
   Develop consistent rules for distinguishing `PART`, `KIT`, `SERVICE`, `EXPENSE`, `OTHER`, and `UNKNOWN` after reviewing more M and O quotations.

## Revision Process

Update this dictionary whenever manual loading reveals a new source format, ambiguous definition, transformation rule, or valid category. Apply corresponding changes to the ERD and `schema.sql` in the same revision.
