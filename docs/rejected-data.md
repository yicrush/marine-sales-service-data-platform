# 검토 대기 자료 처리

`rejected`는 검증으로 적재가 보류된 견적입니다. 사유는 실행 보고서
`data/processed/etl-*.json`의 `load.rejections`에 남고, 원본 추출 결과는
`transformed.records`에 보존됩니다. 로컬 DB의 실제 적재 상태는 보고서의
`status`, `load` 결과와 DB 조회로 확인하세요.

## 처리 순서

1. 원본 파일을 보관하고 작업용 복사본을 만듭니다.
2. 검토 목록에 원본 파일·시트·견적번호와 판단 이유를 기록합니다.
3. 추출 누락은 코드 지원을 보완하고, 원본 값 오류는 실제 업무 자료를
   확인해 수정합니다. 미확인 날짜·고객·수량·통화·금액을 추정하지 않습니다.
4. 같은 견적번호의 사본은 내용을 비교해 사용할 시트를 선택합니다.
   실제 다른 견적이면 올바른 원본 번호를 확인합니다.
5. 선택한 시트를 다시 검증하고 통과한 자료를 적재합니다.

검토 Excel의 판단·메모는 기록용입니다. 값을 바꿔도 현재 파이프라인에는
자동 적용되지 않습니다. `채택`으로 기록한 자료도 원본 수정 또는 명시적인
시트 선택과 재실행이 필요합니다.

## Windows PowerShell에서 재처리

프로젝트 최상위 폴더에서 Python 의존성을 설치하고 `DATABASE_URL` 등
접속 환경변수를 설정한 상태로 실행하세요. 파일명과 시트명은 실제 값으로
바꿉니다. 원본 파일은 파이프라인이 저장하거나 수정하지 않습니다.

```powershell
.\.venv\Scripts\python.exe -m etl.pipeline "data\raw\검토용.xlsx" --sheet "확인한시트명" --dry-run
```

검증을 통과하면 다음 명령으로 적재합니다.

```powershell
.\.venv\Scripts\python.exe -m etl.pipeline "data\raw\검토용.xlsx" --sheet "확인한시트명" --schema marine --init-schema
```

내용을 확인한 경고가 남아 있다면 선택한 시트의 검증 및 적재 명령에
`--allow-warnings`를 추가할 수 있습니다. 이 옵션은 오류를 허용하지
않으며, 모든 선택 시트의 경고에 적용되므로 검토한 시트만 선택하세요.
품목이 0개이거나 가격 추출이 불완전한 경우에는 먼저 원본 및 추출 지원을
확인합니다. 단위당 가격은 경고를 승인해도 전체 총액으로 바뀌지 않습니다.

## 중복과 기존 데이터

- 한 번에 처리하는 자료 안에 같은 견적번호가 여러 개 있으면 모든 사본이
  보류됩니다. 검토한 대표 시트만 선택하면 다시 검증할 수 있습니다.
- 두 파일을 따로 적재하면 파일 간 중복은 나중 실행에서 기본적으로
  `skipped` 처리됩니다. 두 파일 간 중복도 함께 검토하려면 두 Transform
  결과의 `records`를 합쳐 하나의 JSON으로 Load해야 합니다.
- 기본 `--on-existing skip`은 기존 자료를 갱신하지 않습니다. 추출 코드나
  원본을 수정한 뒤 같은 견적번호를 실행해도 이미 저장된 자료는 그대로입니다.
  기존 저장 내용의 변경이 필요하면 현재 값과 수정값을 비교한 뒤, 선택한
  시트에 대해 명시적으로 `--on-existing replace`를 사용합니다. 이 옵션은
  해당 견적의 품목과 연결 문서를 교체합니다.

`--skip-invalid`는 보류 자료를 제외하고 통과한 자료를 적재하는 옵션입니다.
보류 원인을 해결하거나 승인하는 기능은 아닙니다. 일부 자료가 보류되면
종료 코드가 1이어도 `Committed`로 표시된 자료는 저장되었을 수 있습니다.
